# CDTA IT Operations

Welcome to the **CDTA IT Operations** GitHub organization.

This organization contains code repositories that support internal IT operations across the Capital District Transportation Authority. Repositories here are intended for practical operational use, with a focus on automation, scripting, administration, monitoring, integration, and small internal applications that improve the efficiency, reliability, and security of CDTA technology services.

## Purpose

The goal of this organization is to provide a centralized, maintainable location for internal IT operational code, including:

- PowerShell, Python, Bash, and other administrative scripts
- Automation for infrastructure, Microsoft 365, Azure, Active Directory, and security operations
- Internal utilities and helper tools
- Small web-based and desktop applications for IT staff use
- Configuration templates, job definitions, and supporting documentation
- Code associated with reporting, maintenance, monitoring, and system administration tasks

## Scope

Repositories in this organization are generally intended to support:

- IT infrastructure operations
- Endpoint and server administration
- Identity and access management
- Cloud and Microsoft 365 administration
- Security operations and reporting
- Data extraction and internal reporting
- Internal dashboards, status pages, and lightweight applications
- Process improvement and operational automation

This organization is **not** intended for public-facing customer applications or general software product development.

## Standards

To support long-term maintainability and operational reliability, repositories should follow these principles where practical:

- Clear repository naming
- README and usage documentation
- Defined ownership or maintainer
- Secure handling of credentials and secrets
- Source control for scripts and applications
- Change tracking and version history
- Reusable, supportable code over one-off solutions
- Basic testing or validation for production-impacting automation

## Security Expectations

Because many repositories in this organization may interact with production systems, data, or administrative tools, contributors should follow standard security practices, including:

- Never storing passwords, tokens, or secrets directly in source code
- Using approved secret storage and configuration methods
- Applying least privilege wherever possible
- Documenting required permissions and dependencies
- Reviewing scripts and applications for operational and security risk before production use

## Repository Types

Typical repositories may include:

- `scripts-*` for operational scripting collections
- `app-*` for small internal tools or applications
- `automation-*` for scheduled or workflow-based operational tasks
- `reporting-*` for internal reporting and data extraction utilities
- `templates-*` for reusable operational patterns and starter configurations

## Contribution Approach

This organization is primarily for internal CDTA IT use. Contribution practices may vary by repository, but in general:

- Keep changes focused and documented
- Use pull requests where appropriate
- Coordinate production-impacting changes with the relevant owner or team
- Update documentation when functionality changes
- Retire outdated scripts and tools when they are no longer operationally appropriate

## Intended Audience

This organization is intended for:

- CDTA IT staff
- Authorized consultants and implementation partners
- Administrators and technical staff supporting CDTA internal systems

Access is limited to authorized users and internal operational needs.

## Notes

Repositories in this organization may range from quick operational utilities to more structured internal applications. The common thread is that they exist to support **internal IT operations**, improve service delivery, reduce manual effort, and strengthen operational consistency across the environment.
